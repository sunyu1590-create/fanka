# HEIKA 沉浸式创作编辑器

## 结构与接口

Web 与 Android WebView 使用相同 Next.js 编辑器。`Community.tsx` 保留目标、草稿、媒体、投票、系列、审核提交与 AI 工作台的既有状态及接口；`ComposerPanels.tsx` 提供稳定的文字编辑区、格式工具栏、图片条和带焦点管理的弹层。`app/composer.css` 独立维护创作表面的响应式规则，沿用主题 Token。

主界面顺序为轻量导航、发布目标、标题正文、必要的 AI 资源字段、媒体条、话题摘要、更多设置和固定提交栏。预览复用 MarkdownContent 与 AIResourceDetails，AI 资源预览不会请求版本记录或展示读者反馈表单。

继续调用 `/api/v1/library-state` 的 draft/publish、`/api/v1/ai-space` 的 draft/submit、`/api/v1/media`、帖子媒体接口、分类、话题、系列和 `/api/v1/ai/workbench`。未修改数据库、RLS、审核规则、视频 Beta 开关或媒体数量限制。

## 草稿保护

- 本机元数据先保存，附件使用 IndexedDB；按账号和发布目标隔离，兼容旧草稿与旧附件键。
- 云端写入串行执行；跳过过时快照，失败保留本机内容且可重试。只有确实同步完成才显示账号同步成功。
- 退出编辑会先刷新本机快照；浏览器返回和页面离开也进入保存流程。
- 切换目标会确认，保留公共编辑内容；目标已有草稿时恢复目标草稿，源内容先保存。跨帖子附件使用新 ID 复制上传，避免存储路径关联冲突。
- 已发布作品的修改只在本机保存，提交时仍使用原修订审核流程。
- 签名预览失败不会移除媒体路径；附件列表读取失败时停止云端自动写入并阻止提交，提供重新读取入口。
- 旧的未分区 IndexedDB 附件保留作兼容回退，不执行破坏性清理。

## 原生 Expo

现有原生社区发布页同步调整为标题正文、媒体优先的结构，话题和分类进入弹层；支持图片预览、封面、替换、删除、长按排序、失败重试，以及固定提交栏。保留原有上传和审核接口。原生正文预览与实际详情共用 NativeMarkdown。访客草稿按独立身份保存，身份变化不会复用上一账号的内容，重复提交使用同步锁。

原生工程原本未实现 Web 的 AI 空间资源发布、视频 Beta、系列与投票完整编辑能力，本次没有在原生端复制另一套这些业务；这些能力在 Web/WebView 编辑器完整保留。原生 AI 工作台原入口保留。

## 验证范围

- Web TypeScript、lint、Next.js 生产构建及现有单元测试。
- 原生 TypeScript 和修改文件 lint。
- 浏览器覆盖手机/桌面深浅主题、长标题正文、Markdown 预览、九图限制、拖动排序、封面、替换删除和恢复、云端失败重试与串行快照、话题投票、AI 资源预览、提交审核以及签名失败时附件保留。
- 服务端行为通过接口桩验证请求和状态；没有向生产创建测试作品或捐弃真实用户草稿。
- 未在 Android 真机/模拟器验证软键盘、相册权限和触摸排序；未构建 APK。视频仍受现有 Beta 配置控制，未进行生产大文件上传/转码验证。

扩展运行旧 P0 时，发现两项与编辑器打开之前的界面有关的现存问题：悬浮底栏宽度与旧的全宽底栏断言不一致；超宽桌面详情返回按钮会被导航遮挡。没有通过修改发布页以外的导航样式掩盖这些结果。
